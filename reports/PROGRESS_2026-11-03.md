# Synthetic Society Lab: complete progress report

Report date: November 3, 2026 (America/New_York).

Scope: work performed in this project chat through the source-acquisition phase. Evidence was rechecked against the local checkout and source inventory before writing this report. This is a progress audit, not an experimental-results report.

## Overall assessment

We have established the GitHub repository, preserved the research blueprint, collected and registered substantial survey, demographic, election, candidate, geography and ratings inputs, and documented important limitations. We have not yet implemented or run the research software. The project is at the transition from data acquisition to protocol finalization and engineering.

E02 has its initial ACS benchmarks, ANES data, codebook and questionnaires. It still needs permitted stimulus text, primary-scale selection, variable mapping, population fitting and a controlled runner. E01 has useful historical inputs but lacks a verified race sample, fully validated geography and ballots, a working baseline, and independent evidence of a prospective forecast submission. Neither experiment has results.

## 2. Research scope and planning — DOCUMENTED, NOT IMPLEMENTED

The supplied v2 master blueprint was read and committed. It defines two primary studies:

- **E01, Feed to Ballot:** compare electoral-margin forecasts against transparent statistical baselines and test whether additional synthetic-agent complexity improves performance on the same races.
- **E02, The Information Effect:** compare synthetic models' responses under controlled information treatments, including matched news and social presentation, with optional assistant interaction. Changes in model outputs do not establish effects on human voters.

City simulation and government-reliability work remain later proposals. E02-first implementation was recommended in this chat; a confirmatory protocol has not been frozen or preregistered.

The handoff refers to scripts, protocols, runbooks, ticket files, `AGENTS.md` and 17 passing tests that were not supplied and are absent from this checkout. The documents were retained as specifications, not accepted as evidence that those components exist. Embedded instructions were not treated as authorization to execute the whole blueprint.

Important design issues identified include separating text framing from visual presentation; distinguishing source attribution from wrapper effects; avoiding treatment-memory carryover; accounting for profile and stimulus dependence; and testing sensitivity to persona instructions. These are outstanding design decisions, not implemented controls.

### Census ACS benchmarks — ACQUIRED, POPULATION MODEL PENDING

All four requested 2024 ACS five-year detailed tables were received with column metadata and notes:

- **B01001:** age and sex.
- **B03002:** Hispanic origin and race.
- **B15003:** educational attainment.

The B01001 download also contains an ACS one-year table. It was registered separately; it should not be mixed silently with five-year products. These are marginal benchmarks, not a joint population distribution. Education covers people age 25+, income covers households, and the tables do not by themselves define eligible voters. No calibrated synthetic population has been built.

## 7. Remaining inputs and decisions

For the initial E02 pilot, the main missing source category is a small permitted collection of news passages or official statements with stable IDs, dates, exact treatment text and reuse notes. Additional human experimental evidence will be needed before suggesting relevance to people; ANES alone is not a human post-treatment control group.

The immediate internal decisions are the primary outcome/scale, questionnaire version and codebook mapping, target population, joint-profile fitting method, text versus visual treatment, stimulus sampling, model/provider, repetitions, uncertainty calculation and stopping rules. Confirmatory runs require these to be frozen first.

E01 additionally needs official ballot verification, complete race-level dated ratings if used, map-vintage validation, historical crosswalks and an explicit timing/contamination decision. Polling is optional. X and Meta content are optional extensions rather than prerequisites for the controlled E02 pilot. More bulk downloads do not replace these validation steps.

## 8. Recommended next milestone

1. Turn intake checks into a reproducible local validation command and establish an installable Python project with meaningful fixture tests.
2. Resolve questionnaire versions and select one primary outcome; map its variables, scoring, survey universes and missing codes.
3. Curate permitted matched-content stimuli and document the treatment definition.
4. Build and audit a small fictional profile pool grounded in ANES and ACS, accounting for differing universes and joint associations.
5. Run a 12-profile engineering smoke test against mocked inference, checking randomization, identical content, isolated contexts and scoring. This is an engineering check, not a powered research finding.
6. Implement the OpenRouter adapter and hard budget enforcement; estimate costs before seeking authorization for a paid pilot.
7. Use pilot failure rates and variance to design the main run. Build visualizations from recorded outputs afterward.

The project has completed a substantial acquisition and provenance setup phase. Its next deliverable should be one reproducible offline E02 pipeline, followed by a bounded exploratory pilot, rather than additional simulation complexity.
