# Proposed household citizen18+ benchmark from2020–2024 ACS PUMS

Status: **OFFICIAL METADATA/SOURCE FEASIBILITY ONLY; PENDING INDEPENDENT SOURCE AND METHODS APPROVAL.** November3,2026. No person or housing data file was downloaded, no target conversion or fit ran, and no previous source/config/model was edited. This proposal addresses the ANES household-versus-ACS-group-quarters mismatch without waiving the original nationwide,state-stratified adult population criterion. It does not establish state representativeness or human-response validity.

It exposes CSV/SAS person and housing ZIPs without a login or API key. Only that public index and small official dictionary/guide/accuracy/record-count metadata were read. No paid service, keyed API or access bypass is proposed.

The [2020–2024 dictionary](https://www2.census.gov/programs-surveys/acs/tech_docs/pums/data_dict/PUMS_Data_Dictionary_2020-2024.txt) is dated March5,2026. Use that five-year release, not the2024one-year dictionary. The [five-year user guide](https://www2.census.gov/programs-surveys/acs/tech_docs/pums/2020_2024ACS_PUMS_User_Guide.pdf) and [five-year accuracy document](https://www2.census.gov/programs-surveys/acs/tech_docs/pums/accuracy/2020_2024AccuracyPUMS.pdf) describe weights, subsampling, disclosure protection and replication. The access landing page was readable through the web tool, while a direct urllib request to that landing page returned403; that response is recorded without a raw-byte identity claim or access-control bypass. The official file index and five-year metadata files were directly readable. Metadata byte hashes/observed response headers and exact URLs are recorded in `reports/E02_MATCHED_PUMS_SOURCE_PROPOSAL.json`; they are not hashes of unacquired person archives.

The index reports national `csv_pus.zip` as2.1G compressed. Its full URL is `https://www2.census.gov/programs-surveys/acs/data/pums/2024/5-Year/csv_pus.zip`. National person data are divided into four members PSAM_PUSA/B/C/D; the published record-count metadata lists16,095,728US person records across them, before citizen/age/household filtering. The national ZIP must not be combined with stateZIPs, which would double-count overlapping records.

State-by-state streaming can bound disk/memory use and facilitate resumability, but does not eliminate total network cost. Compressed sizes/record counts suggest a materially large job; uncompressed storage/runtime must be measured on the approved pilot rather than invented. A later plan must set local byte, extraction, memory, runtime and retry bounds before scaling.

## Exact person schema and household exclusion

The five-year dictionary names the current state field **STATE**, character2. Do not assume an older-schema ST field. STATE01..56 includes the50states/DC codes with gaps;72 is PR. Region is available, but a state-region cross-check can use the existing documented FIPS mapping. No PUMA or lower-geography variable is needed for the proposed aggregate.

Required person fields and reviewed candidate coding:

- RT='P' verifies a person record.
- STATE is an allowed50state/DC FIPS code; exclude72 explicitly.
- AGEP is numeric age0..99 with topcoding. Retain18+; coarse age bins18–24,25–44,45–64,65+ are proposed. Do not limit PUMS to80 because the ANES80 code means80+, not maximum age80.
- CIT=1,2,3,4 denotes citizenship at birth or naturalization;5 denotes noncitizen. Retain1..4, with count/weight exclusions recorded; never infer citizenship from residence or birthplace alone.
- RELSHIPP=20..36 denotes household relationships;37 is institutionalized group-quarters population;38 is noninstitutionalized group-quarters population. Retain20..36 and exclude37/38 explicitly. Unknown or malformed relationship codes must fail review rather than be treated as household.
- SCHL is educational attainment. Proposed crosswalk to the existing three categories:01..17=HS_OR_LESS;18..20=SOME_COLLEGE (including associate degree);21..24=BA_PLUS. Blank is defined for under3 and should not be silently accepted for retained18+ records. This field supports an18–24 education benchmark, unlike S0501's25+-only section.
- PWGTP is the positive integer person point weight. Person totals require PWGTP, never household WGTP.
- PWGTP1..PWGTP80 are person replicate weights. Their documented integer range includes negative and zero values. Never filter records or clip weights merely because a replicate weight is nonpositive.

TYPEHUGQ is a housing-record variable:1housing unit,2institutionalGQ,3noninstitutionalGQ. It is not listed in the person schema. A person-only RELSHIPP filter therefore avoids claiming an unavailable personTYPEHUGQ field and avoids a housing merge or retaining SERIALNO. SERIALNO/SPORDER/PUMA, exact income, birthplace detail and other unnecessary microdata fields are not inputs to the minimal aggregate. If a future study needs household-specific attributes, that is a separate approved join/source scope; it must not enter this parser implicitly.

The dictionary also verifies allocation flags FAGEP,FCITP,FSCHLP and FRELSHIPP (0not allocated,1allocated). The minimal quality extension may keep only aggregate counts/weighted shares for those flags. Do not drop allocated records by default: doing so changes the weighted target. A separate prereviewed sensitivity can assess allocation dependence. Report allocation/error rates without exporting records.

This selection targets **citizen18+ persons living in households** in50states/DC, not “heads of households,” households as units, likely voters or all group-quarter residents. In-person ANES covers48states/DC while fresh web covers50states/DC, and both exclude group quarters; the PUMS household citizen filter is a better candidate coverage alignment than all-resident S0501. Address-frame eligibility, usual-residence rules, timing, recruitment, nonresponse and interview modes still differ. The match is partial, not a scientific acceptance certificate.

## Proposed minimal aggregate and arithmetic

After approval, a separate versioned streaming aggregator would project only RT,STATE,AGEP,CIT,SCHL,RELSHIPP,PWGTP,80replicate weights and the four approved allocation flags from each person row. It would validate exact headers and code domains against the pinned five-year dictionary, preserve the original archive unchanged locally, and write only aggregate artifacts. Parsing a wideCSV still reads archive bytes, but need not persist unused columns or rows in staging.

Accumulate sums of PWGTP into state×four-age×three-education cells:at most612cells. Also retain unweighted contributing counts, sum of squared point weights for a descriptive weight-concentration diagnostic, separate exclusion counts/weights and allocated-share diagnostics. Produce all80replicate sums for the same selected records/cells using the same age/education/citizenship/household classification. Aggregate to state, region and national margins from this single consistent joint table, so age and education share coherent totals without rounded-percentage multiplication. No individual record is copied into a fictional persona. Party/race/income remain existing ANES-model fields; PUMS does not supply partisan opinion or identify their full state associations from a demographic benchmark.

PUMS PWGTP already represents the five-year period-average population through the published five-year weighting procedure. The accuracy document describes division by five during weight construction. **Do not divide the released five-year PWGTP or replicate weights by five again**, and do not concatenate one-year inputs into these files. Integer weight sums are exact arithmetic on released weights, not exact census totals or a count of unique humans observed once over five years. PUMS is a subsample with confidentiality edits and can differ from published ACS tables. Keep the original S0501 target artifacts as a separate, differently defined universe; do not force household-only totals to equal S0501all-resident totals or treat their disagreement as parser failure.

This route avoids S0501 one-decimal percentage conversion for joint age/education targets, but not sampling error, integer weight rounding, age perturbation/topcoding or other disclosure-processing effects. The accuracy document describes age and weight perturbation. Young-adult threshold comparisons and ANES election-day age therefore require sensitivity/transport review. Income rounding/inflation is irrelevant to this minimal field projection; do not add income merely because it is present.

## Replicate uncertainty, covariance and precision limits

For a released-weight aggregate estimate X and replicate estimates X_r, the documented SDR variance is:

    V(X) = (4/80) × sum_r (X_r − X)^2; r=1..80.
    SE = sqrt(V); conventional90%MOE =1.645×SE.

For a proportion, recompute numerator and denominator with each matching replicate weight before forming each X_r. Do not average individual percentages or divide replicate numerator by the point denominator. Aggregate weights can be negative in a replicate even though point weights are positive; do not repair that by clipping. Zero/nonpositive replicate denominators or undefined estimates must be preserved as quality failures and block unsupported interval output pending a reviewed rule. Preserve legitimate zero/negative replicate inputs as documented.

Joint aggregates/replicate totals allow a covariance estimate(4/80)×sum_r[(X_r−X)(Y_r−Y)], subject to the same release and design assumptions. This improves upon pretending independently published marginalMOEs identify covariance. It does not automatically propagate PUMS uncertainty through a fitted synthetic generator or combine PUMS and ANES sampling error. Any such propagation needs its own frozen method and audit. Full80replicate target vectors may be signed and are not automatically feasible nonnegative calibration targets; do not rake a generator to them by default.

Official accuracy guidance discusses zero estimates/zero estimatedSE, control totals and alternatives involving design factors;2024 is the last publication year for design factors. A minimal implementation should label these cases and block naive confidence claims rather than invent a positiveSE or silently declare certainty. Review any fallback using the correct five-year design-factor release separately. Uncertainty estimates exclude all-source total error: imputation/nonresponse, disclosure processing, period/coverage transport and synthetic political-response validity remain. Do not label any resultingMOE a guarantee that a state synthetic population is representative.

## Privacy, provenance and bounded reproducibility plan

Public PUMS availability supports a permitted acquisition candidate, not permission to redistribute all raw rows, reidentify people, link to private/voter files or send records externally. Keep raw archives and any necessary extraction ignored locally; never commit or upload person rows/household keys. The aggregator projects no identifier, location below state or political targeting information, and exports only the reviewed coarse aggregate schema. Unweighted counts/low-support flags require disclosure review before sharing; keep failing/sparse aggregates local if approval is unclear. No formal differential-privacy or anonymity guarantee is claimed.

Before acquisition, independent source/methods review should freeze:official URLs/product/period, exact pilot scope and byte limits, approved field allowlist/crosswalk/universe, exclusion/error policy, replicate variance rules, aggregate schema, disclosure policy and permitted retention. Then a new manifest can record sourceHTTPdates/collectiontime/rights, exact downloaded ZIP/member SHA-256 hashes, compressed/uncompressed bytes, member names and actual headers. Directory modification dates are not independent proof of source publication clocks. Preserve source drift as blocked evidence; no silent replacement, unbounded retries, alternate keyed route or restricted source fallback.

Fixtures must first test:citizen1..4 versus5; household20..36 versus37/38; actualSTATE schema; age18/25/45/65 boundaries and80+; correct SCHL recode including young adults; positive point weights but signed replicate weights; held-fixed eligibility across replicates; hand-known sums/covariances/proportion denominators; duplicate/archive overlap prevention; source drift and malformed/suppressed data; all51state/DC coverage; and aggregate-only output. Distinct pilot/replay runs must match aggregate hashes. Use official record-count and verification-estimate metadata to verify the unfiltered file and matched-universe checks where available; do not force arbitrary filtered target cells to equal a table with a different universe.

The full national job must select either nationalA–D members or51state/DC archives, not both. Track manifests at archive/member level and refuse duplicates; retain all required pieces and expected record counts. Run locally with bounded memory and reviewed checkpoint semantics; resume must not double-add completed batches. Cost here is local compute/storage/network, not modelAPI spend; no monetary estimate is invented. Independent auditor must recompute pilot aggregates and uncertainty before national scaling or target conversion, and separately review any later model fitting.

## What remains blocked

No bulk acquisition, aggregator code,18+target run or population fit is authorized by this metadata proposal. Independent source/method approval is next. The original ANES source/mapping/weights/split and prior negative results remain unchanged. Expanding ages/states is a separately reviewed model amendment, with precise cohort identity and existing-split inspection disclosed. A household citizen benchmark can strengthen age/education/state alignment and benchmark young education, but cannot identify missing state-level political correlations, fix ANES sparse cells, validate51state effects, establish human persuasion or make12profiles nationally representative. Original population completion remains INCOMPLETE/BLOCKED until those requirements are independently met.
