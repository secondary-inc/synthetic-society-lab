Each state is a bounded failure/checkpoint unit; retaining all original compressed sources permits local replay without another request. Freeze this route before requests. A failed state does not authorize switching to the national ZIP or dropping that state. A partial collection remains incomplete.

Logical published part names are not a verified literal ZIP-member inventory: exact filenames/case, companion files, ZIP sizes/hashes and headers remain unknown. The national archive has one large acquisition failure unit and requires all-four-member streaming/checkpoint support. It avoids 50 new state requests but offers no demonstrated runtime/memory advantage. Never combine national rows with state rows or acquire both strategies as an automatic fallback.

The recorded [official five-year index](https://www2.census.gov/programs-surveys/acs/data/pums/2024/5-Year/) lists all51 state/DC person archives separately from PR and housing files. This is planning arithmetic on rounded labels with assumed units, not an exact transferred-byte total. No housing file, Puerto Rico archive, API key, private service or account login is needed for the proposed person-only scope. This document relies on existing evidence and makes no newly fetched current-source claim.

## Proposed resource envelope — not authorization

Use one network request/processing worker at a time, zero automatic retries and no HTTP range resume. The state route allows at most50 new person GET attempts plus one exact local Wyoming reuse; the national alternative allows one person GET instead. The five metadata reconstruction requests are complete under their separate approved envelope. Any additional metadata requests require a separately reviewed envelope and must not consume or imply person-data request authority. Network received bytes across every attempt, including failed/partial reads, are capped at3GiB; unique compressed inputs including cached Wyoming are independently capped at3GiB. Neither counter resets on process restart. The cap may stop a valid release; stopping preserves a truthful blocked state instead of increasing it automatically.

## Cancellation, resumption and source integrity

One durable batch ledger contains immutable route/design/metadata pins,51 state assignments, attempt IDs, unique source hashes, byte/time/row quotas, source dispositions and append-only stage events. Lock it across processes. Record and fsync the attempt/config and request/remaining-budget reservation before dispatch. Quotas count bytes already received even when an attempt fails. On abrupt termination, any request whose durable state cannot prove completion is consumed and reconciled conservatively; unknown usage blocks further dispatch.

Stop dispatch on the first error or cancellation. Flush type/status-only failure metadata, retain partial bytes/quarantine identities, terminate the worker process group, preserve completed aggregate checkpoints and leave the final benchmark BLOCKED. Do not retry a failed URL or range-resume its partial ZIP automatically. Failed-source retry needs an explicit reviewed continuation with old usage carried forward; unattempted sources can resume only under an unexpired valid approval/ledger and available cumulative allowance.

Resume only after code/design/source and metadata revalidation. Fully received immutable archives can be reused locally without a GET. Persist per-source input and output hashes, expected/actual row counts, schema and source file identity. Source hash/member/actual-size/postprocessing binding must match the reviewed Wyoming guard. If a CSV/member is interrupted, restart that source's parse from its immutable archive with fresh counters charged to the cumulative processing ledger; never append duplicate partial counts. Each successful state is committed once per sweep by a deterministic state/source/config key. A second replay writes a separate output cohort. Final merge demands all51 distinct states, expected per-state/national record totals, zero ambiguous/incomplete states and matching provenance. Order-independent merging/replay and deliberate duplicates must be tested.
