# One-request compatibility executor v4: methods proposal

Design only. The accepted production-admission v4 foundation remains unchanged.
This proposal grants no real price/model selection, bootstrap, human approval,
key access, network model request, paid execution or scientific acceptance.

## Smallest next implementation

Add a separately versioned executor and a fixed authenticated transport wrapper,
with authored tests and a private offline recorder. Preserve the accepted v4
price/owner/factory modules, HTTP v2 and all survey code. Do not activate the
existing always-refusing `run_live_compatibility` entry point by editing it.
The new executor will have a conditional positive path, tested with fake OS
accounts and private stub transport/key boundaries; actual release remains
absent. No arbitrary public transport, URL, owner path or clock injection.

The only request is the existing compiled nonpolitical JSON probe, one exact
run/unit/phase and an independently released output limit. No survey, fictional
population, human persuasion, repair prompt, fallback, stream, tools, plugins,
BYOK or inference retry. A correct result is exactly a JSON object containing
`ok: true`; an invalid answer is a charged compatibility failure, not a reason
to dispatch again or silently discard a billed observation.

## Acyclic code and authority binding

Before any actual state or key access, derive an execution contract containing
the exact new executor/transport code pins, accepted dependency receipt pins,
one-request algorithm, error/record schema and network/lookup limits. It contains
no approval, future run journal or review that would hash itself. The foundation
review's `limitations_sha256` must equal the canonical hash of this contract;
a separate independent executor review binds contract, foundation release and
foundation review. The operator assertion already binds that exact foundation
review hash, so it also binds the execution contract. This extends the external
workflow without changing the frozen owner schema or creating a receipt cycle.
Actual review and operator assertions are never authored by the implementing
agent. Test assertions are explicitly simulated, not human authentication.

Verify all bindings before calling the existing admission factory. The factory
retains fixed fresh-public-metadata acquisition and key gating. Public metadata
GET, one authenticated model POST and at most one authenticated generation GET
are distinct recorded operations. No account changes or credit purchases.

## Dispatch, billing and recording

Create a private run and immutable execution-start record before reservation.
After successful admission, derive exact request bytes again, persist STARTED
through the fixed owner and retain the receipt in the run journal before POST.
Transport construction performs no request. Reserve precedes the single POST;
the same admitted bytes must be sent. Persistence failure before POST halts.
A crash after reservation or any uncertain dispatch never automatically replays.

The transport uses only fixed OpenRouter HTTPS paths and reviewed bounded
request/response parsing, no redirects, proxies, cookies, identity headers,
arbitrary opener or retries. Keep socket15s/body2MB/cooperative elapsed30s
limits; no absolute OS timing, TLS compatibility or verified shutdown claim
follows from stubs. Any new wrapper must preserve rather than conceal existing
transport uncertainty and safe error behavior. Credentials remain in memory,
opaque/redacted, absent from journals, exception text and persisted bodies.

Persist a valid generation identifier and any safely observed charge before
statistics. Do not substitute a requested provider for actual serving identity.
Use the existing owner statistics-claim barrier before its one GET for that
same generation. Accounting may continue under original authority after expiry
or clock failure; it cannot start new inference. No polling schedule or retry.
Missing/nullable/mismatched model/provider/native usage/BYOK/cost, invalid
generation, transport cancellation or billing failure retains conservative
unknown/overrun charges and the global unfinished barrier. Retain greater known
charges immediately even if later validation fails. Reconcile completion and
generation cost/usage without assuming missing fields are zero. Check native
prompt/output/reasoning bounds and every released fee assumption; reasoned or
auxiliary-service behavior outside the text-only contract halts.

After authoritative billing, settle even an invalid visible answer, then write
the exact key-free output/usage/quality checkpoint and commit it with the owner.
No subsequent request is allowed without the global phase commitment. Preserve
the original charge, generation, approval epoch, price proof, actual reported
provider, native usage, request and output hashes, errors and exclusions. A
terminal run status cannot erase an unfinished owner phase. If local persistence
fails after durable success, preserve uncertain caller outcome for independent
read-only resolution; no automatic deletion, replay or invented failure marker.

Use a narrow persisted schema; never copy arbitrary response fields or hidden
reasoning. If a response contains credential material, refuse persistence and
retain a type-only failure/conservative reservation rather than log the body or
derive a credential fingerprint. Compatibility records stay private and are
not automatically admitted to the generic viewer, research analysis or export.
Development costs and credit-purchase/tax/account fees remain separate/unpriced.

## Acceptance before any actual release preparation

Independent review must test conditional positive fake-OS execution with one
stub POST/one stub statistics GET, exact request rederivation and retained raw
history; missing/changed outer code/reviews/assertions before OS/catalog/key;
reserve/journal-before-POST; two-process contention; lifetime count across new
runs/cheap answers/renewals; invalid JSON/shape and charged quality failures;
null/wrong model/provider/usage/generation/BYOK/cost; known-cost disagreement,
overrun, unknown billing, expired/rollback/unavailable time accounting; all
transport cancellation and real process-death/persistence boundaries; no retry,
duplicate statistics, cross-run receipt or checkpoint substitution; and key/body
privacy. Preserve prior components and failure evidence unchanged. Run supported
Python3.11/3.12 targeted tests and relevant existing regressions. Record a private
authored primary control with exact byte/hash/count/cost oracles; no scientific
effect or actual provider observation can be inferred from it.

Only after exact code/raw acceptance can a concrete genuine price/review/owner
bootstrap/one-request approval package be prepared. Fresh price interpretation,
dedicated rotated key and explicit nonzero owner approval remain external
dependencies. The first real call remains NOT_RUN and is not authorized here.
