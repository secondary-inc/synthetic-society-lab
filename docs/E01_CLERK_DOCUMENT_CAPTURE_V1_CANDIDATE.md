## Exact limits and authority

The separate script `scripts/e01_clerk_documents_capture_v1.py` fixes the two
literal URLs/roles and all caps. A fresh release must bind the exact root,
script hash, sources and limits by an externally supplied **canonical JSON**
plan hash. A matching independent code review must have status
`PASS_BOUNDED_CLERK_DOCUMENT_CAPTURE_V1_CODE`, auditor role
`independent_auditor`, the script hash and
`source_policy_sha256 = SHA256(canonical({sources:SOURCES,limits:LIMITS}))`.
These are trusted workflow bindings, not human identity authentication.
No such actual release/review is generated by this candidate or its tests.

At most2GET attempts, one worker,8MiB application-body bytes per source and16MiB
in total. Each request has a45-second cooperative timer and15-second blocking
socket timeout; the whole unit has a120-second parent timer, including receipt
closure. Nested timers preserve the earlier parent remainder. This does not
claim an absolute OS/TLS/wire bound or an always-writable failure record.

The create-once fixed output scope is
`data/raw/e01_clerk_documents_capture_v1`. Minimum free space is64MiB. Raw/partial
payloads are at most16MiB, metadata at most1MiB and total retained data at most
17MiB. At most seven metadata records, each at most64KiB, fit within that metadata
cap. A PDF is promoted by same-directory rename without copying. Output parent
mode is0700 and created files0600. Root/metadata/scope aliases are refused;
bounded metadata reads reject identity/content changes while permitting access
time updates. No hostile ancestor-swap or complete OS sandbox claim is made.

The exclusive scope and durable STARTED reservation precede dispatch. Each source
has its own durable intent. Partial bytes and full reservations remain after
errors, cancellation, missing acknowledgments or death. Existing—even empty—
scopes refuse rather than resetting. No retries, HEAD, redirects, alternative
query/host, browser/proxy fallback, cookies or credentials. A first-source
failure prevents the second source from starting. Failed/unknown persistence
may leave only earlier markers; those still prohibit another invocation.

Content-Length above the cap or malformed, encoded content, HTTP error/redirect,
incomplete body, non-PDF content declaration/signature and observed close errors
stop. Unknown-length bodies require EOF below the cap; exact-cap bodies without
verified completion receive no extra-byte probe. Verified declared-length
completion is distinct from admitted PDF status. A `%PDF-` signature is not
structural PDF validation; there is no PDF parsing, execution, rendering,
candidate projection, baseline calculation or roster adoption in this stage.
