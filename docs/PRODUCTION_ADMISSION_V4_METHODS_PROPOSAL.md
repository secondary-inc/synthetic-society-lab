# Production admission v4: proposed engineering milestone

Status: methods proposal; independent review pending. All actual owner bootstrap, human approval, credential access, model calls and experimental spending remain zero. Preserve every accepted fixture ledger/client/journal, the HTTP helper and common runtime unchanged. This milestone prepares production-capable controls using authored tests, without treating those tests as a real release.

## Scope and first eventual execution

Implement separate modules for complete text-endpoint price contracts, a fixed production owner ledger and a release-checking factory. Reuse independently accepted arithmetic/state-machine rules, but never relabel a fixture owner, quote, approval or transport as production. Positive tests use isolated authored OS-account homes and explicitly simulated external decisions; they do not initialize the real account namespace or authenticate a human.

The first eventual real request should be a separately approved one-request JSON compatibility probe with authored nonpolitical input, not an E02 attitude experiment. Its exact prompt, response schema, output ceiling, single unit/phase, model/provider policy, price bound, timeout and one statistics lookup must be frozen before asking for authority. No real call is included here. A later finite-cohort pilot and the full research program retain their separate scientific/population/source/attrition gates. Successful compatibility would establish only the observed API behavior of that request.

## Price-contract admission

Detach finite built-in inputs before validation. A quote requires an externally expected contract hash, exact metadata receipt/body digest, model ID, route policy and reported-provider mapping, allowed parameters, complete applicable fee interpretation, validity interval and independently reviewed source/interpretation decision. Absence of a price field never automatically means zero. Unknown fee, tier, override, reasoning, cache-write or auxiliary-service applicability refuses a complete quote. Dynamic latency/uptime observations are not fee evidence.

Freeze a text-only request policy with no files/images/audio, plugins, tools, server tools, response cache, BYOK, model fallback, inference retry or repair prompt. Use only a documented supported output-limit parameter. Preserve a conservative exact-message input-token envelope and upward rounding per request. Bound every permitted caching/reasoning/token/request component; do not silently discard extra pricing keys. A reviewed conservative overbound is allowed and must explain its algebra. Record actual reconciled cost separately from the reservation. Credit purchases, taxes, account-plan fees and development costs are separate and never automatically purchased or included as invented per-call fees.

Freshness checks apply to NEW dispatch. Retained old quotes remain mathematically verifiable and cannot become unreadable when their price or approval expires. Accounting for an already dispatched phase continues under its original authority, with honest clock-error metadata. New metadata may refresh only an explicitly reviewed semantic contract; changed fees, supported parameters, route membership or meaning cannot silently replace the released plan. Do not require mutable performance telemetry to be byte-identical, or mistake a fresh timestamp for price authentication.

Current candidate metadata remains unreleased. The successful2358-byte catalog snapshot has two Azure tags; the base route is a provider family rather than a guaranteed region/hardware endpoint. A possible engineering policy must bound every eligible family member and explicitly state unobserved region/revision limits, or choose and verify a specific supported endpoint. Do not infer exact regional service from a reported provider name. No endpoint/model selection or missing-request-fee interpretation has been accepted here.

## Fixed owner and authorization

Use the OS-account home resolver, independent of checkout/output/HOME/XDG. Production entry points accept no alternate owner path and never bootstrap on open, resume or missing state. Bootstrap is an explicit separately authorized create-once action, initially with zero allowance; retain an outside-inner-store bootstrap registration so a missing ledger is not mistaken for first use. Missing/torn registration/header/history/head refuses. Complete coordinated replacement of protected authority remains outside the declared local integrity boundary; no hostile-host or cryptographic human-identity claim is added.

Owner authorization is an external human workflow assertion under trusted execution. The program must validate its exact released proposal, owner/bootstrap identity, predecessor, time interval, absolute lifetime total/module caps, and allowed study/plan/request set. The agent must not author an affirmative real approval. A JSON boolean, supplied key, fake review or successful fixture is not consent. The eventual owner action and artifact must be concrete and reviewable. This code stage leaves real approval absent.

Money alone does not express a one-request authorization: include absolute lifetime dispatch ceilings and released unit/phase/run bindings. A new run/output path, cheap actual answer or renewed approval cannot allow unlimited repetitions of the same authorized probe. Count reservations across epochs, including uncertain ones, with no retry/refund/reset. Validate every historical reservation against its historical approval, plan and price contract. Enforce module caps and owner-wide generation uniqueness; require exact durable phase commitment before further dispatch. Renewal retains all earlier consumption and cannot clear unfinished/unknown/overrun barriers.

Persist STARTED before any eventual inference. Preserve known charge and original identity before statistics; at most one lookup for the same valid generation. Late expiry/rollback/unavailable clock never suppresses existing-phase billing. Unknown/overrun retains at least reserved or greater known charge. Fresh reservations/approvals refuse on time errors. Context binds original release/plan/approval/price evidence, run/unit/phase/module, exact payload/message digests, seed/parameters/token bounds and per-call count. Trusted code must rederive the actual request; a caller's opaque hash alone is insufficient.

## Factory and credentials

Validate independently released code, request plan, complete/fresh price contract and explicit owner authority before resolving/creating production state or reading any credential. Actual construction/initialization remains disabled until those concrete releases exist. Read neither `.env` nor old exposed credentials. Rotated dedicated-key setup is an owner action; do not print, hash into reports, persist, place in prompts or pass keys on command lines. No automatic purchase, top-up, key creation/rotation or account-setting change is authorized.

The eventual transport must retain fixed HTTPS hosts/paths, no redirects/proxies/cookies/identity headers, bounded request/response/time, no streaming and no arbitrary opener. Public catalog GETs, authenticated account/statistics checks and model POSTs are distinct recorded operations. Actual serving/billing/native usage remain unverified until an owner-approved request; nullable/missing identities or accounting do not become success by guessing. A later transport/journal integration must record actual calls/costs rather than copy fixture zeros.

## Acceptance criteria

The authored implementation must pass: complete fee algebra and per-request fractional rounding; absent/unknown/tier/cache/reasoning/auxiliary fee refusal; metadata and contract alias mutation; changed semantic contract and stale/future/rollback freshness; output-parameter and route-family identity limits; fixed OS-account namespace with environment/checkout relocation negatives; create-once zero bootstrap and missing/torn inner/outside state; no actual owner/key/network effects in tests; explicit one-unit/one-dispatch authority across runs/cheap settlement/renewals; historical money and count limits; concurrent requests; uncertain/overrun/expiry/cancellation; real process deaths around registration/reservation/billing/checkpoint/head; exact request/receipt/checkpoint binding; safe error/projection/logging; and refusal before credential access for every incomplete release.

Use authored catalog/approval/review fixtures and stub transports only, labelled as simulated external authority. Test production path resolution through a mocked OS-account home in isolated temporary directories, not through a public relocation switch. Independent review must inspect side-effect counters and raw history rather than accept flags. Actual-owner/human/fee/provider/TLS compatibility remains untested. Run supported-runtime checks and preserved dependency regressions, then obtain independent code/raw review before any real release preparation.
