# Global billing v2: offline implementation candidate

Status: implemented and lead-tested; independent code/control review pending. This implements the next component of the accepted live-v2 design, not a production release or an authorized study. Existing `model.py` and accepted `survey_execution.py` remain unchanged.

## What is implemented

`GlobalFixtureLedger` creates an explicitly simulated owner scope once. Run IDs, output directories, module changes and process restart share the same explicitly opened control directory; they do not renew its total/module allowance. Missing database/anchor/bootstrap marker or a changed policy refuses reopening rather than creating an empty allowance. Production owner identity, fixed external control location, authorization verification and bootstrap are not implemented; creating a separate fixture scope is deliberately a test-only operation, not proof against a malicious host deleting all authority files.

Every reservation atomically records the complete phase identity, frozen endpoint terms, exact request/message count and conservative token envelope, seed/temperature/no-retry policy and full payload hash. Requests are deduplicated by run/unit/phase/module, including changed requests/seeds/terms. The envelope uses the existing standard-library adapter's byte/framing bound; it is an engineering bound, not a proof about arbitrary provider-added hidden context. Price ceilings must serialize without decimal drift. Each reservation rounds up independently to microdollars and includes the explicitly specified request fee.

The owner ledger rederives charges/reservations and validates typed history against its separate anchor. SQLite changes commit before the anchor advances; a crash between them intentionally blocks reopening rather than rolling back known work or granting a new allowance. An interprocess lock serializes mutations. There is one unfinished phase at a time across all runs/modules. New requests are blocked at STARTED, RESPONSE_SEEN, SETTLED, UNCERTAIN or OVERRUN; only a validated durable phase checkpoint releases the global phase barrier. Settled costs remain consumed. Unknown billing keeps the full reservation or greater known cost; overruns remain recorded and halt. No retry/refund/reconciliation reset API exists.

`ReconciledFixtureClient` dispatches only through the exact owned `FixtureHTTP` class; that class performs no network operations and accepts no credentials. The authored chat envelope omits the unguaranteed top-level serving provider. One same-generation metadata lookup establishes its declared actual provider, model, native token counts, billing mode and total charge. A different generation's cost is not attributed to this phase. A nullable chat cost may be resolved by the authoritative matching metadata. Null/wrong provider, mismatched model, unknown/native-over-limit tokens, unsupported reasoning, BYOK, fee disagreement or lookup failure hold the global ledger. This version supports only the authored non-reasoning fixture terms, not a real endpoint's fee/reasoning contract.

Safe scalar billing evidence is durably stored before SETTLED. Arbitrary generation metadata, private reasoning, external user identifiers, referrers and user agents are not retained. Only redacted user-visible answer text is returned in a separate quality envelope; malformed/non-object/refused answers remain quality records with settled billing, not repair prompts or fabricated numerical responses. Instrument scoring, invalid-pre skip and complete assignment accounting belong to the separate phase runner. A checkpoint binds the exact answer envelope/receipt/request/unit/phase; direct generic transition cannot mark a phase committed without that validation.

The production factory always refuses before any key lookup or transport. No real network transport, credentials loader, owner authorization checker, authentic fresh prices, frozen real study slots, adaptive-post cost plan or live phase-runner integration is claimed. Provider revision/weights are not proven immutable by a declared model name. Large-history replay/storage/performance and bounded real HTTP behavior remain additional release work. Local integrity is not hostile-host authentication or an OS/storage-failure guarantee.

## Execution and evidence

Run `.venv/bin/python -m unittest tests.test_live_billing_v2 tests.test_survey_execution tests.test_budget -q`. The initial v1.0 candidate had16 new tests alongside the existing24 bridge/adapter tests. The v1.1 remediation totals are recorded in the versioned section below. No source/person data, credentials or real inference are used. Positive policy amounts, rates, native usage and charges in these cases are authored simulation only; actual experimental model/API spending is zero.

Cases cover owner-wide cross-run/module ceilings and restart; create-once/missing-state refusal; exact phase deduplication under changed request/seed/terms; reservation-before-POST; billing-versus-durable-phase distinction; serving/null/ID/native-token/fee checks; timeout/cancellation and preserved overruns; malformed/refused answers without retries; unsafe metadata omission; counter corruption; torn anchor persistence; exact phase checkpoint; actual spawned-process death before POST, before stats, after settlement and between database/anchor commit; two-process reservation race; nullable chat cost and foreign-generation cost; and disabled production factory. Zero extra transport calls are asserted on refusal.

Acceptance requires an independent reviewer to rederive reservations/owner totals, probe coordinated event/counter/anchor and phase/route corruption, reproduce actual process/persistence boundaries, inspect fixture-only/privacy guarantees and check the limits above. The existing private bridge runs and new mutable ledgers remain ineligible for review packages without a separate approved disclosure derivative. Passing these tests is not full MODEL_CONTROLS, human/state validity, owner spending authority or external publication.

## v1.1 remediation candidate

Independent review withheld acceptance of v1.0 despite40 passing tests. IA-GLOBAL-V2-GENERATION-001 demonstrated reuse of one previously committed generation identifier for a different phase/answer, including a second statistics lookup. The candidate now checks owner-wide generation uniqueness before binding the new response or looking up statistics, on ledger transition, and during complete semantic history reconstruction. A duplicate response leaves the new reservation UNCERTAIN without attaching the already-consumed generation identity; no lookup/retry/refund follows. Even a fully coedited/rehashed history containing two receipts with that same generation must fail reopening.

IA-GLOBAL-V2-KNOWN-COST-002 demonstrated a resealed terminal record whose charged amount was lower than its unchanged known observed cost. Uncertain/overrun validation now independently requires consumed funds to be at least the larger of the original reservation and the known observed charge on every write/reopen, not merely at least the reservation. Both unknown-route and overrun corruption cases are tested with resealed event/charge/anchor records and zero additional transport calls.

Original source/tests/design are preserved at commit `dbd2e0d`, consumed evidence in `SURVEY_GLOBAL_BILLING_V2_CANDIDATE_V1_0.json`, and the independent finding report remains unchanged. The current candidate has18 new global-ledger tests,42 with the prior bridge/adapter suite. These are still authored fixture controls only; fresh independent closure, real HTTP/owner/global-location/study/price release and live phase integration remain separate.
