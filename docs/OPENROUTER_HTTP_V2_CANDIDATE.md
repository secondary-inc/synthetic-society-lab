# Bounded HTTPS transport: unreleased component

The new internal `openrouter_http_v2._OpenRouterHTTPS` implements the low-level transport needed by the accepted live-v2 design. Independent acceptance and integration are pending. Both existing live client and new live transport factories always refuse. The accepted fake client still requires its exact authored transport type. This component is not a released route around owner authorization or the global ledger.

No credentials are loaded. A future accepted factory must inject a rotated credential only after owner, study, source, price, global reservation and phase admission. The component accepts only fixed OpenRouter HTTPS chat-completion POST and same-generation metadata GET URLs. The official cached OpenAPI SHA33c53c85504e0f3a314d834a179c731597493d24ad68d4f0ba0193824184012e documents those paths; it does not establish actual endpoint behavior or current prices. Generation identifiers use the documented bounded safe alphabet. There are no alternate endpoints, automatic retries, proxy inheritance, cookies, referrer, application/user identity headers or response-content lookups. TLS uses the standard library's default verification context; redirects are refused.

Limits: 262,144 encoded request bytes; 2,000,000 decoded UTF-8 response bytes plus one byte for overflow detection; fifteen-second socket timeout; thirty-second elapsed-time checks before/after reads and after parsing. These are cooperative limits, not an OS wall-clock guarantee: DNS, native networking and a blocking socket operation can exceed an elapsed check. Chunked framing is accepted through urllib; ambiguous Content-Length/Transfer-Encoding or duplicate framing headers, compressed responses, non-JSON media types and non-200/final-URL mismatch refuse. Strict decoding rejects duplicate JSON members, nonfinite numbers, invalid UTF-8 and non-object envelopes. Responses and HTTP error bodies are closed, errors omit remote messages/body/credential, and cancellation closes an already-open response. No response content or request credentials are logged by the component.

Eight new network-free test methods cover exact methods/URLs/headers, zero-request pre-dispatch refusal, redirect/proxy/cookie policy, HTTP status/framing errors, streaming overflow and close, strict JSON, timeouts/sanitized errors and disabled factory. With the prior billing/bridge/adapter suite, fifty tests passed locally. The fake opener exercises transport policy and resource/error paths; it does not verify live TLS, network scheduling, provider behavior or a complete ledger/transport/phase integration. No real network request, credential lookup, model call or experimental spend occurred.

Remaining release work includes fixed owner control/bootstrap, verified authorization, authentic endpoint prices/fees, a complete adaptive request plan, integrated global-ledger HTTP client, pre/post journal coupling, scientific/attrition acceptance and independent review. The existing uncertainty/no-retry rules must surround this transport before production use; low-level HTTP success cannot settle a financial or scientific phase on its own. No paid execution is approved by this change.
