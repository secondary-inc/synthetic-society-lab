# One-request compatibility executor v4 candidate

Authored engineering candidate, pending independent implementation/raw review.
Actual price/model/provider/bootstrap/review/operator/key releases remain absent.
No real owner namespace or environment key was read, and no model/network call
or experimental spend occurred. The accepted foundation and its disabled entry
point remain unchanged. A new conditional executor is tested through private
mocked boundaries; it is not an actual release or a scientific experiment.

`production_compatibility_v4.py` derives an acyclic execution contract over exact
code/dependency receipts and a one-request policy. The foundation review binds
that contract through `limitations_sha256`, its operator assertion binds the
foundation review, and a separate executor review binds contract/release/review.
These remain trusted external workflow assertions, not authentication of a human.
Static failures precede workspace/OS-home/catalog/key access. The installed
editable checkout and its accepted receipt files are required; a wheel without
those receipt artifacts fails rather than dispatches.

A private run directory is created once for the preassigned request ID beneath
`data/processed/compatibility_runs`. It is separate from the default recorded-run
viewer directory. Immutable artifacts, chained event files and a checksum ledger
record the release, exact admitted request/context, reservation-before-POST,
one claimed generation lookup, scalar billing, quality checkpoint and global
owner commit. Existing run directories are not resumed or overwritten. A new
output workspace cannot reset owner money, dispatch counts or phase identity.
The generic viewer is not a DLP service; deliberately presenting arbitrary paths
or metadata to another viewer is outside this default-directory separation.
No compatibility data is added to the research dashboard or export bundle.

Exactly one canonical byte request is passed to a fixed authenticated transport.
It uses the accepted HTTP component's fixed-host/no-proxy/no-cookie/no-redirect
construction and strict bounded parsing. A separate checked implementation
propagates observed response-close errors. Socket15s, response2MB and elapsed30s
limits are cooperative, not absolute OS/TLS/shutdown guarantees. No native call
through this new transport has been made. HTTP error and cancellation handling
never retries inference. A valid JSON answer is exactly one `ok` member whose
value is the JSON boolean true; numeric1, duplicates and extra fields fail.

Safely attributable known cost is retained before other response/billing failures,
including a later credential-body refusal. Completion overrun becomes terminal
UNCERTAIN immediately, without statistics, because STARTED cannot transition
directly to OVERRUN under the frozen state machine. Generation overrun becomes
OVERRUN. Missing/null/wrong generation/model/provider/native usage/BYOK/cost and
completion-cost disagreement retain conservative charges and the global barrier.
Completion usage is checked where present; mandatory authoritative native usage
is not assumed identical to a possibly different reported tokenizer. Reasoning
usage must be zero. Monetary scalars are bounded in length/exponent before exact
upward microdollar rounding. Unsupported accounting remains unknown, not zero.

Visible answer quality is separate from billing: invalid answers still settle
and commit their charged quality failure. No repair or repeat follows. Keys
never enter request messages, artifacts or error strings. Full untrusted bodies
are screened before output hashing/persistence; only visible text and scalar
allowlists are retained, never hidden reasoning. Private raw fixture responses
are explicitly authored, not provider observations. The fresh metadata body
itself is not returned by the frozen foundation; its exact digest/time and
validated semantic contract are retained, not a claim of a full fresh-body
archive or independent future reacquisition.

Eight real spawned exits cover reservation, POST intent/return, response,
statistics intent/return, durable phase and owner commitment. A two-process
different-output race permits only one global request. Tests also cover late
expiry/rollback/unavailable-clock bookkeeping, privacy, invalid static releases,
unknown/overrun billing, no dispatch after failed journaling, and a durable owner
commit/final ledger with lost acknowledgment and modeled read-only logging.
That last case may raise to the caller while preserving a valid committed
observation; exceptions are not proof of no commit. Preserve state for independent
read-only resolution, without automatic retry, deletion or invented tombstones.
No real read-only mount, directory-fsync/power-loss, hostile-host or coordinated
authority replacement guarantee is claimed.

The final private authored example contains one stub POST, one stub generation
GET, two stub metadata GETs (one later refusal), one stub key access, one simulated
microdollar and a PHASE_COMMITTED owner row. Two repeat attempts use the same and
a different output workspace; neither reads another key, changes the owner or
dispatches. The second workspace may retain a failed private journal, honestly
distinguished from zero writes. Earlier control01 remains historical evidence
from before the checked-close transport and final additional tests.

Reproduce with `PYTHONPATH=src:tests` and either supported Python interpreter:

```

.venv/bin/python scripts/record_production_compatibility_v4_fixture.py --directory data/processed/fixture_scopes/production-compatibility-v4-NEW
```

authority or transport option, and patches OS-home/clock/catalog/key/transport.
The evidence JSON pins code/tests/recorder/doc, logs, raw index and preserved
dependencies. No new scientific, forecasting, representative-population,
human-persuasion, public-release or paid-execution acceptance follows.
