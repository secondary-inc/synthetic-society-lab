## Cancellation, resumption and source integrity

One durable batch ledger contains immutable route/design/metadata pins,51 state assignments, attempt IDs, unique source hashes, byte/time/row quotas, source dispositions and append-only stage events. Lock it across processes. Record and fsync the attempt/config and conservative full-attempt body reservation before dispatch. Quotas count application-returned body bytes on proven success; failed or unprovable attempts consume their full reserved allowance, including after restart. On abrupt termination, any request whose durable state cannot prove completion is consumed and reconciled conservatively; unknown usage blocks further dispatch.

Stop dispatch on the first error or cancellation. Do not retry a failed URL or range-resume its partial ZIP automatically. If a CSV/member is interrupted, restart that source's parse from its immutable archive with fresh counters charged to the cumulative processing ledger; never append duplicate partial counts. ## Application-delivered HTTP BODY accounting and crash consumption

The proposed3GiB person-request allowance meters response BODY bytes delivered to the Python application by a bounded `response.read(n)` call, or exposed to it as a partial body on a read exception. It does not meter HTTP headers/transfer framing, hidden client buffers, TLS/TCP/IP/proxy traffic or retransmissions. Unexpected Content-Encoding is rejected; no implicit content decompression is allowed. Completed five-file metadata usage has its own separate ledger. This proposal does not claim an implemented quota or a hard wire-traffic ceiling.

Prefer conservative full-attempt reservation over optimistic file-size accounting. Before each state GET, lock and durably fsync the batch ledger with a384MiB attempt reservation deducted from remaining body allowance. Block if a full allowance cannot be reserved. No reduced allowance, fresh batch ID, process restart or new approval may silently replenish historical usage. The national3GiB reservation belongs only to the alternative if a separately approved route selects it; it is not an escape hatch in the frozen state route.

Before every read, persist its sequence/inflight state and requested `n`, bounded by64KiB and remaining attempt allowance. Do not issue a read/EOF probe after that allowance is exhausted. After a normal return or a read exception exposing partial bytes, charge the actual application-visible length exactly once and fsync its receipt before clearing inflight state. Future fixtures must verify the selected client's read-size, partial-error and encoding behavior. If an observable delivery violates the bound, record the actual overrun and stop; do not erase it to claim compliance. Content-Length is a precheck, not evidence of actual receipt or identity.

Unused full-attempt reservation can be released only after provable EOF, response closure, all per-read receipts durable, terminal body-count/hash/file-identity agreement and an atomic committed ledger transition. A verified successful attempt then consumes its observed body count. Any failed, cancelled, interrupted or unprovable attempt consumes its FULL reservation permanently, even when a retained partial file is smaller. A crash between a read return and its receipt cannot reset usage to the file size or zero. Outstanding inflight reservations remain consumed and block dispatch until durable reconciliation. Unbounded/unknown usage, corrupt ledgers or uncertainty outside the verified channel blocks further requests pending separate review. Record both observed bytes and conservatively charged allowance so a cost report does not present the latter as measured traffic.

Socket/HTTP/TLS/OS buffers may already hold response bytes not delivered to the application. Closing a socket or timing out cannot undo such receipt. Those bytes and lower-layer overhead are outside this application counter's coverage; any wire cap would require a separately metered transport absent here. The application channel and durable full-attempt charge provide conservative application-budget accounting, not stronger network-traffic or physical-byte guarantees. All implementation, restart/cancellation/error fixtures and independent verification remain N1 work.

## Primary replicate guidance and exact same-release rule

The retained [2020–2024 accuracy document](https://www2.census.gov/programs-surveys/acs/tech_docs/pums/accuracy/2020_2024AccuracyPUMS.pdf), PDF pages12–13, specifies80 replicate weights per person, calculating each replicate estimate with its correspondingly numbered weight using the same procedure as the full estimate, then SDR4/80 squared deviations. It permits signed replicate weights and warns that sampling standard errors omit nonsampling error. Exact retained SHA-256: `edbc9973f8cdf1a6528bb9acc450d83e230edc66421aa708ec9892a087b86447`.

The retained [five-year user guide](https://www2.census.gov/programs-surveys/acs/tech_docs/pums/2020_2024ACS_PUMS_User_Guide.pdf), PDF pages6,10–12, describes national five-year data split into four parts, person PWGTP and PWGTP1..80, the same-index SDR recipe, and available state/region domains, with DC included nationally and PR separate. Exact retained SHA-256: `77f9b74efef7cb9d3eb8ffa4dc875df9e15765432d6134ead3691a5fe8b35e1a`.

Applying this general estimate recipe to the disjoint union from ONE pinned2020–2024 release means: for each r=1..80, first sum each state's selected PWGTPr numerator/denominator into the national or regional numerator/denominator; calculate that replicate's total or ratio; then apply SDR against the corresponding full-weight estimate. Cross-state/cell covariance follows from the jointly indexed replicate deviations. Never average state ratios, add state standard errors, assume independence and add variances, reshuffle replicate indices, or mix annual/five-year/other-release weights. National and state source rows are alternative partitions, never additive samples.

This is an explicit application of the official general same-index rule, not a claim that either retained document contains a verbatim cross-state ZIP compatibility guarantee. Release/version/partition/schema identities still require enrollment and actual-source checks; hashes of metadata alone cannot certify unknown person files. Independent N0 review must assess this source-grounded rule, and N3 must verify a separate arithmetic oracle. No new source/technical chapter was fetched or invented to strengthen that attribution.

## Candidate universe versus the original adult/state goal

The current candidate benchmark is citizens aged18+ living in households in all50 states/DC, averaged across2020–2024. It excludes every noncitizen and both institutional and noninstitutional group-quarters residents. It therefore is not all U.S. adult residents and, if the intended target is all adult citizens, it still omits citizens in group quarters. Citizenship+age+household residence does not verify electoral eligibility, registration, turnout propensity or likely voting. These distinctions must appear in every derived target/model label.

State demographic margins cannot validate state political-response distributions. Retain all51 states and missing-support warnings rather than dropping states to produce an apparent fit.
