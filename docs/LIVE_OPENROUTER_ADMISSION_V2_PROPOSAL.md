# Proposed live admission and global billing release v2

Status: **DESIGN ONLY; implementation/release/owner authorization absent**. Preserve the accepted offline bridge v1.2 unchanged. This proposal closes the remaining live engineering gap without treating fake transport or simulated ledger amounts as live readiness.

## Public schema evidence

The official [OpenAPI document](https://openrouter.ai/openapi.json), acquired without credentials on November3,2026, is cached locally/ignored. Exact body SHA256: `33c53c85504e0f3a314d834a179c731597493d24ad68d4f0ba0193824184012e`;2,729,603bytes,HTTP200. The `ChatResult` schema does not declare a top-level serving-provider field. The generation lookup schema includes a nullable serving-provider name, native token counts and total USD cost. Its global authentication requirement applies to that lookup. This proves a documentation contract, not observed live behavior. The older [official overview](https://github.com/OpenRouterTeam/docs/blob/main/api_reference/overview.mdx) also describes generation-stat lookup by the completion's identifier. No such authenticated lookup was attempted.

Inference for this project: current fake envelopes supplying a top-level provider cannot establish real route compatibility. A future client must not substitute the requested route for an unobserved actual route. It needs an independently reviewed generation-stat reconciliation path or other documented authoritative serving identity. Missing/null/disagreeing identities remain unknown and halt dispatch.

The [official routing guide](https://github.com/OpenRouterTeam/docs/blob/main/guides/routing/provider-selection.mdx) describes price ceilings per million input/output tokens and optional per-request pricing. Therefore token prices alone cannot certify a universal bound for an arbitrary endpoint; each approved endpoint's complete fee structure needs review. No provider/model or actual price is approved here.

## Required release contract

1. Freeze one concrete study plan: instrument/protocol/analysis, profiles and target universe, permitted source text, all matched simpler controls, model identifier and serving-endpoint identity, sampling/error/exclusion rules and allowed parameters. Independently accept exact code/input hashes before live admission. Keep prospective/human persuasion claims disabled. Full-adult demographic coverage, conditional political priors, unknown domains and finite synthetic estimands must remain distinct.
2. Validate an explicit owner authorization artifact against the reviewable plan, positive total/module limits, expiration and required rotated credential setup. A supplied key or fabricated approval string is not authority. This is workflow evidence under trusted execution, not cryptographic proof of a human's identity. The agent may not author its own affirmative authorization. Keys are injected only at the final enabled boundary; never logged, committed or put in prompts. No credentials were read for this proposal.
3. Use one fixed durable **owner-wide** ledger for all studies/modules/runs under the approval. Creating a run, process, model or new output directory cannot create a fresh allowance. Atomically reserve upward-rounded worst-case cost with the run/unit/phase/request/price/approval binding before POST. Preserve old charges across restart and changed approvals; no replenishment without explicit reviewed authority. Unknown or outstanding dispatches block subsequent inference across that ledger.
4. Derive pre-call envelopes from the exact messages. Valid post baselines are adaptive: bound their serialized length and every allowed numeric representation before execution, then enforce the bound on the actual post request. Invalid baselines follow the independently accepted skip rule. Freeze output/possible reasoning ceilings, complete endpoint fee/tier/caching rules, request limits and time/response limits. Reject unbounded or undocumented costs. A maximum price preference alone does not make a local reservation adequate.
5. Keep one pinned route, no provider/model fallback, no tools/plugins/repair prompts and no automatic inference retries. Demonstrate that the exact endpoint supports all required parameters and JSON administration. Record the provider's actual identity; require an explicit frozen mapping if the catalog route slug differs from its reported name, never a guessed normalization.
6. Persist STARTED before inference. Record a valid generation identifier and safe billing fields before the phase can settle. If generation statistics are needed, specify a tiny independently reviewed bounded lookup schedule for the **same** identifier, with byte/time limits and no fresh inference. A missing/late/failed lookup retains the conservative reservation, blocks the global ledger and preserves a reconciliation case. No inference retry or charge refund follows from a timeout, cancellation or HTTP error. Do not fetch generation content or private reasoning.
7. Reconcile the returned identifier/model/actual route, usage, total charge, BYOK status and relevant native-token/fee breakdown against the frozen request envelope and prices. Unknown provider, unknown billing, unsupported extra fees or overrun halt. Preserve actual charge evidence even when a survey response is invalid. This is not a guarantee that a provider cannot bill above its advertised ceiling; an overrun must remain a recorded failure with owner review, not disappear from the ledger.
8. Couple the global reservation identity to the phase journal before dispatch. Bridge v1.2's exact request/output/route/seed/token checks and phase-pair checkpoint guards must extend to the shared ledger without treating other runs' receipts as this run's completions. A crash between reservation, POST, billing lookup, journal commit or checkpoint commit never silently replays. Explicit reconciliation uses copied immutable evidence; it is not an automatic retry switch.
9. Preserve complete assignment/quality/invalid counts. A separately reviewed live analysis must address arm-dependent missingness/attrition and finite-cohort interpretation; complete-case mock resampling is not a full-cohort causal or human-effect certificate. Keep scripted Q&A separate from a live assistant; assistant and swarm conditions require their matched simpler/equal-compute controls.
