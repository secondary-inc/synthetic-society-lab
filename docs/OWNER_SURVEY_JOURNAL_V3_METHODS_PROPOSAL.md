# Owner-epoch survey journal v3: authored integration proposal

Status: methods proposal, independent review pending. This closes the accepted owner-client component's missing own-prior-response and durable run/journal binding. It authorizes no implementation until independently reviewed, and no actual source, model, owner bootstrap, human approval, fee, HTTP, credential or spending release. The old bridge and all accepted components remain byte-identical.

## New surface and study binding

The lead owns a new `survey_owner_execution_v3.py` and tests. Reuse the exact accepted owner fixture, owner survey client, adaptive planner, request/scoring helpers, PhaseJournal and RunStore. The new production entry always refuses. No constructor or per-run path creates/grants/resets an owner allowance or accepts arbitrary transport. Existing owner and exact fake transport are explicit dependencies; their fixture scope remains visible in every run.

A pure compiler detaches input trees, validates the existing engineering instrument and original registered notice hashes, fictional profile ID/party-only schema, bounded seed/repeats and exact fixture terms. It derives assignments and every adaptive request plan, capped at180 jobs for this bounded integration. It freezes code pins, input/assignment/plan/script hashes and invalid-response policy into a study specification. The executor requires its separately expected study hash and rederives the exact specification before creating/resuming a run or dispatching. This hash is a trusted external binding, not proof of human consent or scientific release. No demographics or new treatment is introduced.

The immutable run configuration binds that specification, owner identity/directory and software/runtime. An explicit `expected_approval_hash` argument selects authority for new calls. Do not include the latest mutable active epoch/head in the immutable run configuration: clean renewal and other completed owner runs must not invalidate earlier completed phases. Each historical dispatched phase retains its own original epoch, plan, receipt and context. Never replace old epoch fields with the newly supplied epoch.

## Per-phase ordering and own baseline

For each unit, rederive the pre request from its frozen job/instrument. A post request can use only the parsed valid output from that same unit's already verified, charged and committed pre phase. It cannot accept caller-supplied survey responses. Recompute visible-answer parsing, quality status, exact messages/quote and response/charge/checkpoint bindings before any reuse. Invalid pre responses retain private evidence and yield scoring-null values and an explicit skipped post with no owner reservation or fake call; no imputation or synthetic replacement.

Persist STARTED in the phase journal before calling the client. The journal request is a new explicit envelope containing the exact survey request, frozen plan hash and explicitly selected approval hash. A skipped post has null approval binding and no receipt. Dispatched phase context must equal an independent reconstruction using the journal's original epoch, owner-verified history, own job/unit, fixed seed, plan, payload and quote. New calls still pass the externally expected plan and approval to the accepted client; its owner reservation precedes fake POST.

After SETTLED, write the exact private phase checkpoint, finish the journal row with the raw visible answer/quality/completion binding, then call the owner's existing durable checkpoint API. Only after owner PHASE_COMMITTED and full semantic revalidation may the paired own-state marker advance. This marker includes immutable config/owner identity, journal hash, own charges and own phase-file hashes. It excludes unrelated completed runs and the mutable latest approval/head, while the owner itself still replays its entire protected history. No uncommitted global phase may be ignored because it belongs to another run.

## Resume, renewal and failures

Resume requires the existing run, all immutable inputs, journal, paired marker and checkpoint files. No missing file/store may be created or repaired on resume. Every own receipt must correspond exactly once to a journal phase and vice versa; reject unknown unit/phase/file, orphan charge, foreign receipt and changed request/quality/billing/epoch. Check all prior phases against their recorded original authority; use the newly supplied explicit epoch only for the next new dispatch. The owner still requires current validity, allowed plan and remaining lifetime/module caps.

A clean `stop_after_phases` pause happens only after owner commitment, paired marker and complete semantic verification. An explicit renewal outside the executor may then preserve all earlier costs and permit resume under a new epoch. The executor never renews automatically. Expiry during an already reserved request still permits billing/checkpoint under its old epoch. The next call remains gated. Expiry or another refusal between journal STARTED and owner reservation may leave a recorded failed attempt with zero corresponding owner charges; the failure report must distinguish this from a dispatched uncertain phase and must not invent cost. Such failed attempts are not automatically retried or erased. Clean renewal/resume is demonstrated from the explicit clean pause, not by silently repairing an interrupted attempt.

Any interrupted phase, torn marker or unresolved owner charge blocks resume without a separately reviewed reconciliation workflow. A crash after owner commitment but before marker advancement also blocks that run's automatic replay. The charged committed row is preserved; other correctly completed/new owner runs may continue if the global owner has no unfinished phase. Stale pair detection must not pretend the owner has an unfinished phase when it does not. No automatic charge refund, restart in a fresh namespace, reconciliation or retry is provided.
