# Production E02 survey phase bridge v5 — methods proposal

Design only. No implementation, actual owner access, credential read, network request, positive budget or live release is authorized. `configs/production_survey_v5_methods_proposal.json` freezes the proposed interfaces, zero/null authority, dependency hashes, boundaries and acceptance gates. Existing code stays unchanged.

## Verified engineering gap

The accepted v3 survey client and journal use an exact fixture owner and fake HTTP. The production v4 admission factory rederives one fixed nonpolitical compatibility payload. The fixed production owner supports pre/post phases, but its allowed plans bind exact request hashes; its public grant validator admits the fixed compatibility release. These components cannot simply be connected by swapping a transport or setting a flag.

The post survey includes that unit's own valid pre answer, so its exact request bytes are unavailable before the pre phase completes. A production bridge must admit that derivation under an owner-approved study policy. It must not fabricate future auditor approvals, treat arbitrary answer arguments as its own prior response, or silently replace the expected approval epoch with whichever one is current.

This component addresses E02. It neither implements the E01 forecasting client nor lowers the original nationwide adult/state population, real stimulus, matched-comparator, evaluation or publication requirements.

## One explicit policy, bounded derived phase bindings

A future operator execution assertion must explicitly approve a frozen study policy, its independent review and code/input/template hashes, exact owner/run identity, model/route/terms, time window, maximum new phase count, and absolute cumulative lifetime money/module/dispatch caps. Those values are zero or null in this proposal. A key, account credit limit or general research instruction is not such an assertion.

The policy must expressly delegate derivation of exact pre/post request bindings within those fixed limits. This is the mechanism proposed for an autonomous approved run; it does not authorize the assistant to choose a budget. Independent methods review must first accept the delegation/admission design. If a safe auditable bridge to the existing owner cannot be established, implementation remains blocked rather than manufacturing a review assertion or bypassing the fixed v4 validator.

One independent parent review signs the frozen study, derivation rules, code and terms. It does not claim to have inspected unknown future response bytes. No runtime component creates an `independent_auditor` review object for a generated post request. A separate v5 admission and derived-grant bridge must validate the parent review, the owner's explicit delegation, the exact phase proof and current original owner state. Only that reviewed bridge may append a linked ordinary owner approval containing the derived exact request binding. It must retain the unchanged owner's event, funds, dispatch, clock and unfinished-phase checks; it must not call the v4 fixed-request admission workflow and claim that it admitted this different study.

Each derived epoch can narrow the allowed plan map to the exact approved phase request. It cannot increase funds/counts, extend the operator's deadline, add units/conditions, change inputs/templates/model/sampling, or reset historical consumption. The same owner and registration are retained. Prior approvals remain in history, and previous phases keep their original epoch. Any existing unfinished or uncertain phase blocks a new grant. This includes the unresolved run03 compatibility request; this proposal supplies no reconciliation, refund, replacement owner or exception.

Pre requests derive solely from the frozen compiled unit. Post requests derive solely from the same unit's committed, independently reconstructed valid pre checkpoint. No public API accepts arbitrary messages, a caller-supplied pre score, owner path, opener or model override. A missing/invalid pre answer records a skipped post with no grant, reservation or request. Fixed run/unit/phase keys and atomic original-owner checks must prevent a second output root or concurrent process from redispatching the same phase.

## Request and journal lifecycle

The first implementation has an engineering ceiling of180 frozen units and two phases per unit, at most360 model POSTs per approved study. This is a ceiling, not an approved sample or a budget. Actual study size must be frozen and priced before owner approval. A phase has one POST, at most one generation statistics lookup after valid identity, and at most one bounded fresh public price observation. No model retry, repair prompt, statistics polling, provider fallback or automatic policy renewal is permitted.

The proposed transport retains fixed OpenRouter endpoints, exact opaque admitted credentials, verified TLS, proxies/redirects off,15-second socket and30-second cooperative per-request bounds,262144-byte request and2000000-byte response limits, strict framing and duplicate/nonfinite JSON refusal. The existing4096-token owner ceiling is an upper bound; the frozen plan must supply a smaller appropriate output ceiling. Model-native usage and the actual serving provider must be checked, not inferred from the requested route. Public price metadata is a separate bounded request and is not a model call or a scientific result.

The journal first records policy/unit/phase/epoch/request intent. The owner reserves before POST. Safe known costs and a valid unique generation identity are retained before any statistics lookup; response identity, provider, native usage, auxiliary activity and reported costs must reconcile. A durable own phase checkpoint precedes owner commitment and paired-survey state. Only a fully committed predecessor allows the next phase. Source/code/assignment/terms drift blocks before side effects.

Unknown billing retains at least the reservation or higher known cost and the global barrier. A lost reservation acknowledgement is UNKNOWN, never proof of zero consumption. An invalid visible answer with verified billing is a charged quality failure, not a retry; invalid pre answers skip their posts and remain in attrition accounting. Cancellation accounts conservatively and then propagates. Unwritable/torn artifacts preserve uncertainty rather than invent a clean outcome. Closed safe diagnostics reuse the accepted status/stage principles; secrets, raw exception strings, bodies and headers are never logged as error explanations.

All request/response/checkpoint/owner details remain private and unbundled pending a separate projection review. Scoring rederives the existing frozen instrument and registered contrasts from verified saved outputs. Recorded-artifact replay performs no model call. A new stochastic model draw is a separately budgeted repetition, even with the same seed; deterministic mock replay is not a real-provider reproducibility claim.
