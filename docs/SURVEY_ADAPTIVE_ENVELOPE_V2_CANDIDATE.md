# Adaptive survey request envelope candidate

This offline planning component prepares the pre/post byte and cost bounds required by the accepted live-v2 design. Independent review and phase-runner integration are pending. It dispatches no requests, reads no credentials and grants no authority. Pricing currently uses the explicitly authored fixture-only terms supported by the accepted quote function; it cannot approve authentic endpoint fees.

For an exact frozen engineering instrument and job, compilation freezes the baseline quote and a conservative post-response envelope. The post surrogate uses two32-character strings instead of unknown thermometer numbers. Those strings add quoting/escaping overhead and are never sent, scored or represented as respondent answers. The supported runtime uses IEEE binary64; each actual admissible built-in numerical value must encode within32characters. Values are preserved exactly as parsed; the planner does not round them. The exact message serializer, system text, quote implementation and source bytes are pinned. A baseline without the exact two finite built-in numbers in0–100 produces an explicit skipped-post/no-request/no-quote disposition. Huge integer, boolean, null, unknown/extraneous-field and refusal cases are included. The existing instrument/scoring code remains unchanged.

Every phase preparation first checks a separately supplied frozen plan hash, then independently rederives the complete plan from its job, instrument, terms and current pinned code. A mutable plan, its internally repeated hashes or self-consistent replacement job are insufficient to satisfy an unchanged external binding. The future release artifact must supply that binding from independently accepted study/cost evidence; this component does not authenticate its caller or manufacture that approval.

Preparation reserializes the exact actual post request and recomputes its quote before any future reservation. Encoded message bytes, token bound and rounded reservation must not exceed the frozen post bound. Both phases include output ceilings and a separately upward-rounded request fee; the sum is a conservative two-phase planning amount. Invalid baselines skip post without returning a usable request. The caller must still atomically reserve the actual request through the shared ledger before HTTP. The quote's existing framing bound is an engineering limit, not a guarantee about undocumented provider-added context, authentic pricing, reasoning or other fees.

Seven new test methods cover exact-own-baseline preservation/isolation, extrema/subnormal/negative-zero and hundreds of seeded finite IEEE values, invalid/no-post disposition, semantic price/bound/source-pin corruption, externally bound replacement-job refusal, per-phase rounding, serialized replay and phase/instrument rejection. Combined with HTTP/global billing/old bridge/adapter,57 tests pass. No actual source population, randomized scientific effect, live protocol or attrition acceptance follows. Plans retain fictional profile/request inputs and must remain private/local-only until separately reviewed for disclosure.
